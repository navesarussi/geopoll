# apps/web – בטא: משאל אחד עם הצבעה חשאית וסקר עמדות פומבי

> **משאל הדגמה – נתוני דמה.** לא לשימוש מול משתמשים אמיתיים. מימוש מפושט של [ADR-0017](../../docs/decisions/0017-anonymous-credential-scheme.md), [ADR-0019](../../docs/decisions/0019-modular-identity-tiers-anonymous-vote-core.md), [ADR-0020](../../docs/decisions/0020-dual-referendum-secret-ballot-public-positions.md) ו-[ADR-0012](../../docs/decisions/0012-public-results-display-buckets-batching.md).

## הזרימה
1. התחברות: Google (Auth.js/NextAuth) או "כניסת הדגמה" מאחורי `DEMO_LOGIN=1`.
2. `POST /api/identity/issue` (תחום A): בודק שהחשבון לא קיבל כרטיס בתקופה (חודש), וחותם **עיוור** (RFC 9474, `@cloudflare/blindrsa-ts`, RSABSSA-SHA384-PSS-Randomized). נשמר רק HMAC של מזהה החשבון + תקופה.
3. הלקוח מסיר את העיוורון ושומר את הכרטיס ב-localStorage.
4. `POST /api/vote` (תחום B): נשלח עם `credentials: "omit"`, והקוד לא קורא session/cookies. מאמת חתימה ותקופה, `nullifier = SHA-256(pollId, preparedMsg)`. אותו כרטיס ⇒ אותו nullifier ⇒ ההצבעה **מחליפה** את הקודמת (האחרונה נספרת).
5. **אצוות קליטה:** ההצבעה נכנסת לתור `zone_b.ballot_queue`, ומועברת ל-`zone_b.ballots` בכל `BATCH_INTERVAL_SECONDS` (ברירת מחדל שעה; האחרונה לכל nullifier גוברת). ההחלפה מתבצעת ב-flush שמופעל מבקשת תוצאות (אין cron).
6. `GET /api/results`: צילום מצב באצוות (`SNAPSHOT_INTERVAL_SECONDS`), סף k=50, טווחים ("מעל 100") ואחוזים שלמים.

## רמות אמינות (T-107, ADR-0019)
- `lib/identity`: מתאמים נשלפים (`TierAdapter`) שמחזירים **רק** רמה: T0 = Google (ו"כניסת הדגמה"), T1 = Google + ת"ז, **placeholder** מאחורי `FEATURE_T1_ID=1` (needs-lawyer, #40; עדיין לא נאסף מספר), ו-T2/T3 stubs כבויים.
- הרמה נקבעת בשרת ונקשרת ל**מפתח החותם**: מפתח נפרד לכל רמה (`ISSUER_PRIVATE_JWK_T0..T3`). אם לקוח כותב בכרטיס רמה גבוהה ממה שנחתם, האימות נכשל.
- הרמה נשמרת עם הקול, והתוצאות מסומנות "רמת אימות בסיסית" כשיש קולות T0/T1.
- **מחיר פרטיות:** הרמה גלויה לשרת ההצבעות, ולכן קבוצת האנונימיות היא כל בעלי אותה רמה. ברמה עם מעט משתמשים זה מצמצם את ההסתתרות; לכן הסף k חל, ופילוח לפי רמה לא מוצג.
- פורמט הכרטיס עבר ל-`geopoll|v2|<epoch>|<tier>|<nonce>`. כרטיסי v1 שנשמרו במכשיר לא תקפים, ומי שכבר קיבל כרטיס בחודש הזה לא יוכל לקבל חדש עד החודש הבא (דמו בלבד).

## ממסר (T-110, בטא בלבד)
- ההצבעה ובדיקת "האם נספרה" נשלחות דרך `/api/relay/{vote,vote-status}` (או ממסר חיצוני דרך `NEXT_PUBLIC_RELAY_URL`). הממסר מעביר **רק** את גוף ה-JSON ו-content-type, לנתיבים מרשימה סגורה. הוא מוריד עוגיות, IP/X-Forwarded-*, User-Agent, Referer, Accept-Language ו-client hints, ולא שומר לוגים.
- שרת נפרד: `RELAY_UPSTREAM=http://vote-host RELAY_SECRET=… npm run relay` (מאזין רק ל-127.0.0.1).
- `RELAY_ONLY=1` + `RELAY_SECRET`: ה-API של ההצבעה מקבל רק בקשות שעברו בממסר (השוואה timing-safe).
- **מגבלה:** כשהממסר וה-API אצל אותו מפעיל (בבטא), המפעיל עדיין רואה IP בכניסה. בייצור: OHTTP (RFC 9458) עם מפעיל ממסר עצמאי.
- בדיקת "האם ההצבעה שלי נספרה" מוצגת רק בבטא; `NEXT_PUBLIC_BETA_INCLUSION_CHECK=0` מכבה אותה.

## סקר עמדות פומבי (תחום C)
- רשות בלבד, למשתמש מחובר: עמדה + נימוק (עד 500 תווים) בשם תצוגה שהמשתמש בוחר (ברירת מחדל: כינוי אקראי; המייל לעולם לא מוצג), ותגובות בשרשור (עד 300, עומק 3) – בסיס לפורומים.
- נספר ומוצג בנפרד, מסומן "עמדות פומביות - לא התוצאה הרשמית". אין API/UI שמחבר אותו לקלפי החשאית.
- מחבר מזוהה ב-HMAC עם `CONTENT_HMAC_KEY`, **מפתח שונה** מזה של תחום A.
- מודרציה בסיסית: דיווח (משתמש אחד = דיווח אחד; הסתרה אוטומטית אחרי 3), מחיקה עצמית, מגבלת אורך, 5 פרסומים ל-10 דקות, מסנן מילים מינימלי.

## מסד נתונים
- מיגרציות ב-`db/migrations/` (רצות אוטומטית בעלייה, נרשמות ב-`public.schema_migrations`): סכמות `zone_a`, `zone_b`, `zone_c` בלי מפתחות זרים ביניהן, ותפקידים `gp_zone_a/b/c` (nologin) עם הרשאות לסכמה שלהם בלבד.
- `DATABASE_URL` (או `POSTGRES_URL`) → Postgres. בלי → PGlite בזיכרון (בדיקות/פיתוח; מתאפס).
- בדיקות רצות על PGlite, וב-CI גם על Postgres 17 אמיתי (`TEST_DATABASE_URL`).

## מסד נתונים מקומי (מפתחים וסוכנים)
```bash
scripts/dev-db up      # Postgres 17: docker compose, ואם אין docker – Postgres מקומי (GEOPOLL_PG_DIR)
scripts/dev-db setup   # מיגרציות + תפקידי login לכל תחום + כתיבת apps/web/.env.local
cd apps/web && npm run dev
```
במצב הזה האפליקציה מתחברת **בחיבור נפרד לכל תחום** (`DATABASE_URL_ZONE_A/B/C`, תפקידים `gp_zone_a/b/c`), וה-DB עצמו חוסם גישה בין הסכמות (`tests/isolation.test.ts`). `DATABASE_URL` (בעלים) משמש רק להרצת מיגרציות.

### אצוות מתוזמנות
`BATCH_MODE=scheduled`: הקליטה והפרסום קורים **רק** ב-`npm run batch-worker` (כל `BATCH_INTERVAL_SECONDS`) או ב-`GET /api/cron/batch` עם `Authorization: Bearer $CRON_SECRET`, ולא בעקבות בקשות משתמשים. ברירת המחדל (`request`) נשארת ב-Vercel, כי ב-Hobby אפשר להריץ cron רק פעם ביום.

### נתוני דמה (T-111, #43)
`npm run seed -- 300 42` מריץ תרחיש סינתטי דטרמיניסטי (`lib/dummy/generator.ts`) **דרך הפרוטוקול האמיתי**: הנפקת כרטיס עיוור, הצבעה, הצבעה מחדש, ניסיון לכרטיס שני באותה תקופה, כרטיס מזויף וכרטיס מתקופה אחרת. אם ניסיון תקיפה מצליח, התסריט נכשל. התפלגויות הגיל, המחוז והרמה הן **הנחה** עד שיוחלפו בנתוני מפקד 2022. בינתיים הן לא נשמרות בקלפי (אין עדיין פילוחים).

**הפריסה החיה ב-Vercel עדיין בזיכרון (PGlite):** הנתונים מתאפסים ועלולים להתפצל בין מופעים, עד שיחובר Postgres מנוהל.

## מה מפושט לעומת ייצור (לא להציג כמוגן יותר ממה שהוא)
- **אין Semaphore/ZK:** ה-nullifier נגזר מהכרטיס עצמו, ולכן שרת ההצבעות יכול לקשר בין הצבעות של אותו כרטיס **בסקרים שונים** באותה תקופה (לא לזהות). ZK יפתור.
- **אין ממסר/OHTTP:** שרת ההצבעות רואה IP; אותה פריסה ואותו דומיין לתחומים A ו-B; מפעיל הפלטפורמה יכול תאורטית לקשר לפי זמן/IP. אין הפרדת תשתית.
- **תזמון:** הכרטיס מונפק מיד לפני ההצבעה הראשונה (בייצור: מראש ובמנות).
- **אחסון:** שלוש סכמות באותו DB. מקומית כל תחום מתחבר בתפקיד משלו; ב-Vercel עדיין חיבור אחד/זיכרון. בייצור: DB ושירות נפרדים לכל תחום.
- **flush/snapshot:** מקומית מתוזמנים (worker); ב-Vercel עדיין מופעלים מבקשות. הקלפי מאשרת "נקלטה" בזמן הכניסה לתור, וה"עודכנה" מחושב מול התור והטבלה.
- **מודרציה** מינימלית מאוד; אין ממשק מנהל ואין ערעור.
- **אובדן כרטיס:** מחיקת localStorage = אין הצבעה עד התקופה הבאה (אין שחזור).
- **T0 (Google):** אדם עם כמה חשבונות = כמה קולות. "כניסת הדגמה" = כל לחיצה חשבון חדש.
- קליטה באצוות (ADR-0020) מפושטת: הקול נשמר מיד, רק הפרסום באצוות. אין זמן מדויק בטבלת הקולות.
