# 01 · אבטחה, זיהוי ופרטיות

[← חזרה לאינדקס](../../README.md)

## מצב נוכחי
העיקרון: הפרדה מוחלטת בין **שירות הזהות** (יודע מי אתה) ל**שירות ההצבעה** (יודע מה הוצבע). הגשר ביניהם הוא אישור קריפטוגרפי שלא ניתן לקשר.

זרימה מוצעת: משתמש ← ספק KYC (מסמך + liveness) ← מנפיק אישורים (מקבל רק "מאושר + מדינה") ← ארנק במכשיר (סוד אישי + commitment) ← הוכחת ZK (חברות בקבוצה + nullifier) ← דרך relay ← שירות הצבעה ← ספירה ציבורית שניתן לאמת.

| גישה | יתרונות | חסרונות |
|---|---|---|
| Blind signatures (Chaum) | פשוט, מוכח עשרות שנים | אסימון חד-פעמי, קשה להוסיף תכונות |
| Privacy Pass (RFC 9576/9578) | תקן IETF, ספריות קיימות | מיועד לאנטי-אביוז ולא להצבעה |
| Anonymous credentials (Idemix / BBS+) | חשיפה סלקטיבית של תכונות | מורכב; BBS עדיין טיוטה ב-IETF |
| Semaphore (ZK, Merkle group) | קול אחד לסקר בלי קישור, קוד פתוח | הפקת הוכחות במובייל, ניהול קבוצות |
| MACI | עמידות לקניית קולות | תלוי במתאם מהימן, כבד |

**מודל איומים עיקרי:** קישור קול לזהות על ידי המפעיל, Sybil ובוטים, כפייה, קניית קולות, פריצה לספק ה-KYC, דרישות ממשלתיות לנתונים, דה-אנונימיזציה סטטיסטית והשתלטות על חשבונות. הטבלה המלאה נמצאת ב-PRD.

## החלטות שהתקבלו
- **זיהוי:** תעודה ממשלתית וסלפי עם בדיקת liveness, דרך ספק KYC חיצוני. ראו [ADR-0002](../decisions/0002-identity-gov-id-selfie-liveness.md). המשתמש אישר שזה מספיק, עם ההסתייגויות שמפורטות ב-ADR.

## שאלות פתוחות
- **מניעת כפילויות:** אדם עם שתי תעודות (אזרחות כפולה, תעודה ישנה וחדשה). האם להשוות נגזרת מוצפנת של הפנים (face template) בין כל המשתמשים? איך עושים את זה בלי לפגוע בפרטיות?
- **הספק רואה את התעודה:** אילו נתונים יישמרו אצלנו (מטרה: "מאושר + מדינה" + hash למניעת כפילות) ומה מדיניות המחיקה אצל הספק?
- בחירת ספק KYC: כיסוי מדינות, עלות למשתמש, עמידות לזיופי AI.
- אזרחות מול תושבות מול זכות בחירה: התעודה לא תמיד מוכיחה זכאות.
- איך מבטלים אישור של מכשיר אבוד בלי ליצור קישור לזהות?
- בחירת פרימיטיב קריפטוגרפי ל-MVP (Semaphore מול blind signatures).

## הנחות
> כל פריט כאן הוא השערה או יעד מוצע, לא עובדה.

- **הנחה:** MVP יעבוד עם KYC ← commitment בקבוצת Semaphore לכל מדינה ← nullifier לכל סקר. BBS+ בשלב 2.
- **הנחה:** סוד המשתמש נשמר ב-Secure Enclave / StrongBox ולא יוצא מהמכשיר.
- **הנחה:** מפתחות המנפיק ב-HSM עם threshold signing (3-of-5).
- **הנחה:** מטא-דאטה (IP, תזמון) מטופלת דרך OHTTP relay, אצוות ועיכוב אקראי.
- **הנחה (לא נבדק):** כלי זיוף מבוססי AI משתפרים, ולכן צריך ספק שמתעדכן כל הזמן.
