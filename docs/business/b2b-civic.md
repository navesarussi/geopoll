# שירות התייעצות והצבעה לארגונים (B2B/B2G)

[← אינדקס עסקי](README.md)

## מה זה
אותו מנוע שמפעיל את הפלטפורמה הציבורית (KYC, credential אנונימי, nullifier וספירה שאפשר לאמת), אבל **בסביבה נפרדת לכל לקוח**. ארגון שוכר את המנוע כדי להריץ התייעצות, סקר או הצבעה **משלו**, בקרב אוכלוסייה מאומתת שהוא מגדיר. המשתמש הרגיל מצביע בחינם בפלטפורמה הציבורית, והארגון משלם על הכלי.

## קונים ושימושים (הנחה)
| קונה | שימוש | הערה |
|---|---|---|
| רשויות מקומיות | שיתוף ציבור בתקציב, בתכנון ובתחבורה; "תקציב משתתף" | התקשרות עם גוף ציבורי כפופה לדיני מכרזים (**דורש אימות**: חוק חובת המכרזים והפטורים ממנו) |
| עמותות וארגוני חברה אזרחית | הצבעות חברים והתייעצויות | |
| ועדי עובדים וההסתדרות | הצבעות חברים ואישור הסכמים | **דורש אימות:** דרישות התקנון ודיני העבודה לגבי הצבעות |
| מפלגות (פריימריז) | הצבעה פנימית מאומתת | **רגיש במיוחד:** חוק המפלגות ותקנוני המפלגות (mvp L8, פתוח). מוצע להציע את השירות לכל המפלגות באותם תנאים, ורק בסביבה מבודדת לגמרי מהפלטפורמה הציבורית |
| ועדי בתים, מושבים ואגודות | החלטות קהילתיות | שוק קטן. אולי מתאים לו מסלול בשירות עצמי |

## עקרונות מוצר
- **הפרדה מוחלטת** מהפלטפורמה הציבורית: נתוני הלקוח לא משמשים את הפלטפורמה, ולהפך. ללקוח אין גישה לזהות המצביעים, רק לרשימת הזכאות ולתוצאות.
- **הלקוח מנסח את השאלות שלו**, אבל רק בסביבה שלו. זה לא נוגע לפלטפורמה הציבורית (ADR-0009, "לקוח לא קונה השפעה").
- **שקיפות:** דוח השקיפות (ציר 07) מפרט את סוגי הלקוחות. הצבעות פוליטיות, כמו פריימריז, מפורסמות בשם הלקוח.
- **תמחור (הנחה):** לפי מצביע זכאי או לפי הצבעה, ובנוסף עלות ה-KYC כשהמצביעים אינם משתמשים קיימים.

## הערות משפטיות פתוחות
- **דורש אימות:** האם הצבעה מקוונת תקפה בהליכים פורמליים (אסיפה כללית של עמותה, ועד עובדים) לפי חוק העמותות או לפי התקנון.
- **דורש אימות:** האם אנחנו "מחזיק" (processor) והלקוח "בעל השליטה" במאגר לפי חוק הגנת הפרטיות, ואיזה הסכם עיבוד נדרש.
- **מתי:** אחרי שלב 1 ואחרי ביקורת אבטחה חיצונית (ציר 01). מתאים לשלבים 2–3 ב-MVP.
